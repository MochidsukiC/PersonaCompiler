# 初期プロンプトと設定：灯継町（ともつぎちょう）

**4人が灯台の公開方法を相談し、そこで得た経験を、根拠付きのゲーム用NPCデータへまとめる設定です。**

1分のデモで追う人物は修理職人の「音羽 澪」に絞れます。安全を重んじる管理人、暮らしと商いを考える売店主、正確さを大切にする記録係を同じ場所に置き、短い生活の中で相談と判断が生まれる機会を作ります。合意・対立・信頼関係・結末は事前に固定しません。

## 最初に貼り付けるプロンプト

[01-world-input.txt](01-world-input.txt)の全文を、アプリの地域の説明入力欄へ貼り付けます。画像の添付や追加イベントの入力は不要です。通常の質問カードへの回答と仕様承認を経て、生活開始前の状態まで生成します。

## 画面で選ぶ設定

| 項目 | 推奨値 |
|---|---|
| 親モデル | `gpt-6-astra` |
| 親effort | `high` |
| NPCモデル | `gpt-5.6-sol`、固定 |
| NPC effort | `medium`、固定 |
| 施設モデル | `gpt-5.6-luna` |
| 施設effort | `low` |
| ワールドTier | `3` |
| 演出プロファイル | 生活シミュレーション（`life_sim`） |
| 表現強度 | `1` |
| 台詞方式 | 自由（`free`） |
| 地域・NPCの個別override | なし |
| DEV | OFFのままでよい |

親に世界設計とCompilation、NPCに会話と判断、施設に配置と利用の役割を分担させる構成です。モデルとeffortは接続後の選択欄に存在する場合に採用します。実アカウントの利用可否や、この組み合わせの速度・費用・品質は未実測です。利用モデルと対応effortを取得する仕組みは[OpenAI公式のApp Server仕様](https://learn.chatgpt.com/docs/app-server#models)に記載されています。

モデル設定は「設定を保存して親端末を作成」で固定します。会話演出は「概要」→「会話演出設定」から、初期人口の生成前に保存してください。生成済みNPCに後から遡って適用されません。

## プロンプトに含めた世界設定

| 項目 | 内容 |
|---|---|
| 町 | 灯継町。住民が運営する展示灯台のある海辺の町 |
| 共通の課題 | 計測値に揺れがある展示灯具を、どの条件なら公開実演できるか |
| 人口 | 4人、全員成人、4単身世帯 |
| 音羽 澪 | 24歳・女性・修理職人。試して確かめたい |
| 久瀬 玄 | 58歳・男性・灯台管理人。条件と安全を確かめたい |
| 真砂 杏 | 38歳・女性・軽食売店主。暮らしと収支を両立したい |
| 汐見 律 | 22歳・男性・記録係。発言と解釈を分けたい |
| 年齢配分 | 20～29歳50%、30～49歳25%、50～69歳25% |
| 性別配分 | 女性50%、男性50% |
| 施設 | 住宅街24×24×6、共同広場12×12×4、展示灯台12×12×12 |
| 開始位置 | 全員、共同広場の相談ベンチ付近 |
| 初期経済 | 全員100灯貨、空腹回復60の公開食品を3個ずつ、追加取得費用5 |
| 期間 | 8ターン、1日4ターン、終了条件`turn_limit` |
| 時間の扱い | 実装は4ターンごとに1歳加齢。2年分を圧縮した観察サイクルとして扱う |

点検メモは全員が知る公開の初期条件です。そこから誰と話すか、何を共有するか、何を覚えるか、相手をどう認識するかを本人が選びます。初期位置を近づけることで会話の機会を作りますが、特定の会話・記憶・関係の生成を保証するものではありません。

## 初期生成で確認する点

- 質問カードでは上表とプロンプトに沿って回答する。異なる選択肢しかない場合は自由記述を使う。
- 仕様レビューで4人・3施設・8ターンを確認し、表示中のrevisionを承認する。
- 全員の初期化完了後、`ready / turn=0`で止まる。そこから「1ターン実行」または「生活を開始」を使う。
- 終了後は「概要」のNPCパッケージから「制作レビュー」「Runtime Prompt」「成果物を照合」を確認できる。一時停止だけでは自動Compilationは始まらない。
