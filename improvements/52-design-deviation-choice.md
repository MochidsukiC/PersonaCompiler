# 52 — 設計との差異を許容するか、訂正を指示する

初期人口の年齢分布などが承認済み仕様と異なると、従来はエラーで停止していました。実行を妨げない人口総数・年齢分布・性別比率の差異を、ユーザーが判断する確認画面へ変更しました。

## 機能と試し方

1. 新しいbuildでアプリを起動し、対象ワールドを開いてChatGPTへ接続します。旧版で人口配分のエラーになったワールドも、保存済みの生成結果を再検査して確認画面へ移ります。この再検査にはモデル推論を使いません。
2. 「承認済みの設計との差異」で、承認済み人数と生成結果の人数を確認します。承認された年齢帯の外や、未指定の性別区分も表示します。
3. 「気にせず続行」は、表示した生成人口をそのまま採用し、NPC・施設の初期化へ進みます。承認済み仕様を書き換えず、差異を許容した記録を保存します。人口の再生成はしませんが、その後の通常の初期化処理は進みます。
4. 「訂正を指示」は、差異・現在の人口・承認済み仕様・地図を親Agentへ渡して人口の訂正を依頼します。「訂正指示への追記」は任意です。この操作はモデル推論を開始します。
5. 訂正後に差異がなくなれば初期化へ進み、差異が残れば新しい結果について再び選択できます。

同じ結果への許容は保存・再接続後も有効です。選択前にresult.jsonが変更された場合は、最新の結果を検査して選択し直す画面へ更新します。古い選択を別の人口へ適用しません。

空の人口、不正な形式、重複・予約済みID、不明な所在地、モデル設定違反、家族参照や親子年齢の矛盾などは引き続き処理を停止します。確認画面の対象は初期人口の上記3種類です。特定のゲームジャンルや人物名に依存する条件は追加していません。

## 実装と検証

構造・実行条件の検証と、承認仕様との設計差異の検査を分離しました。差異の記録には生成結果、元ファイルと承認仕様のhash、選択用ID、選択内容・日時を保存します。IPCの既存の入力検証、接続・認証・書き込み制限、処理の直列化を通し、選択時にも元ファイルと仕様を再確認します。旧エラーから移行する際は、解消した該当エラーだけをWorkspaceの表示から消します。

## 戻し方

`git log --oneline -- improvements/52-design-deviation-choice.md`で対象コミットを確認し、`git revert <commit>`、`npm run build`の後にアプリを起動し直します。

許容した差異がある人口を旧コードで再接続すると、旧来の厳格な人口検証で停止します。そのワールドを継続利用する場合は本機能を残すか、仕様に一致する人口のワールドを使ってください。revertは保存データを訂正しません。
